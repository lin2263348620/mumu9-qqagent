# bot-admin

> 原项目作者：**Kondius**，Bilibili 主页：[Kondius](https://space.bilibili.com/14464411)。本项目基于其原项目进行了大幅修改与扩展，是独立维护的衍生版本，并非原作者的官方发行版。感谢原作者提供的项目基础；原项目及第三方代码的版权与许可声明予以保留。


一个可视化管理的 QQ AI bot 项目：把 QQ 登录、模型配置、人设、群聊响应、互动、表情素材和运行诊断放在同一个 Web 后台中。

基于 **Node.js + NapCat + OneBot v11**，支持 OpenAI 兼容的模型接口。当前 Windows 发行包提供中文一键部署入口，自动准备运行环境并创建桌面快捷方式，适合希望先把 bot 跑起来、再逐步配置功能的用户。

> 公开发行包是全新空白项目，不包含预设账号、私人角色设定、API 密钥、聊天记录或登录凭据。首次使用需要自行登录 QQ，并配置模型和接入范围。

## 项目特点

| 模块 | 能力 |
| --- | --- |
| 一键部署 | 检测或下载 Node，安装生产依赖，准备独立 QQ/NapCat 环境，自动配置内部连接 |
| QQ 登录 | 后台扫码登录、账号登录入口、状态刷新、协议端启停与登录恢复配置 |
| 可视化后台 | 对话监控、聊天记录、功能中心、模型设置、人设卡片和运行状态 |
| 主备模型 | 配置多提供商，获取模型目录，选择主模型与备用模型，设置超时和切换策略 |
| 群聊响应 | 安静、均衡、活跃三种模式，呼叫词、普通群聊参与开关与概率、消息合并 |
| 人设与关系 | 自定义角色、头像、称呼、关系备注、群范围与全局关系 |
| 互动与排行 | 投喂、散步、摸摸头、签到、今日运势、好感度与排行榜 |
| 表情素材 | 收藏素材，设置标签、情感备注、适用场景和回复触发概率 |
| 本地数据 | SQLite 保存互动和行为数据，文件保存配置、消息、会话与部分缓存 |
| 运行保护 | 消息去重、发送结果待确认、历史补拉、接收诊断与发送状态追踪 |
| 主动消息 | 主动问候、破冰时间配置、手动触发入口和任务管理 |
| 群聊跟发 | 白名单群内三位不同用户发送相同纯文字后，bot 原样跟发一次 |

后台保留动态光柱/极光背景、导航动效、人设资料卡和 SquishSwitch 开关，同时将能力说明与配置入口集中到功能中心，减少重复设置。

## 快速开始：Windows

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11，x64 |
| 网络 | 能访问 Node.js 官网、GitHub、npm 和所配置的模型服务 |
| 磁盘 | 建议至少预留 1 GB，包含下载、解压和运行空间 |
| QQ 账号 | 能自行完成扫码、设备确认及可能出现的验证 |
| 模型接口 | 自备 OpenAI 兼容接口、密钥和可用模型 |

当前完整 QQ 运行环境未验证 ARM Windows。Linux 部署应使用对应的独立发行包，不运行这里的 `.cmd` 文件。

### 1. 解压项目

将 Windows 空白发行 ZIP 完整解压到固定、可写的目录，例如 `D:\bot`。

不要在压缩包预览窗口里直接运行，不要只提取启动文件。

### 2. 双击部署

运行：

```text
一键部署启动.cmd
```

启动程序会依次完成：

1. 检查 Node.js；缺失或版本低于 22.13 时，下载官方 22.22.0 便携版。
2. 检查 Microsoft C++ 运行库；缺失时下载并验证 Microsoft 签名后安装。
3. 安装后台生产依赖。
4. 下载固定版本的官方 NapCat Windows 独立运行包，并校验 SHA256。
5. 选择可用本地端口，生成内部连接配置和随机令牌。
6. 启动管理后台与 QQ 服务，等待登录接口就绪。
7. 创建桌面 `bot管理后台` 快捷方式，打开浏览器和管理密码文件。

缺少 C++ 运行库时，Windows 可能要求管理员确认或重启，需要本人处理。首次部署必须联网，并保持运行窗口打开。

### 3. 登录后台与 QQ

首次管理密码随机生成，文件位于：

```text
data/admin-password.txt
```

输入管理密码后进入 QQ 登录页面，使用手机 QQ 扫码。建议优先扫码登录；验证码、设备确认和其他安全验证由账号本人完成。

自动准备的是 **包含 QQ 核心的独立 NapCat 环境**，不是完整的桌面 QQ 聊天客户端，无需另外安装桌面 QQ。

QQ 数据保存在项目自身的 `data/qq-profile/` 中，不自动导入电脑已有 QQ 的登录资料，也不修改已有 QQ 安装。

### 4. 配置 bot

| 配置 | 用途 |
| --- | --- |
| 模型 API | 填写接口地址、密钥，选择可用主模型；按需启用备用模型 |
| 人设 | 设置 bot 名称、角色提示词、自定义规则和头像 |
| 主人 QQ | 指定管理权限；留空时不启用主人专属工具 |
| 接入白名单 | 指定允许的群与私聊，空白包不默认接入所有会话 |
| 响应模式 | 选择何时回应，配置呼叫词、群聊参与概率和消息合并规则 |
| 表情素材 | 添加素材及情感标签，设置匹配和触发策略 |

**后台可打开、QQ 服务已启动、账号已登录、bot 能生成回复，是四个不同状态。** 未配置模型或未允许该会话时，不应期待普通 AI 回复。

### 5. 下次启动

双击桌面 `bot管理后台`，或运行：

```text
启动管理后台.cmd
```

项目未运行时启动整套服务；本项目已运行时打开现有后台，不重复启动 QQ 服务。后续运行复用自己的配置和缓存，不重新清空数据。

部署后不要随意移动目录，桌面快捷方式指向部署位置。关闭运行窗口会停止本项目服务，本版不是默认安装为 Windows 服务的后台常驻程序。

## 后台功能

### 对话与运行状态

查看已接收到的群聊和私聊消息、会话存档、处理状态和运行日志。消息展示与是否触发模型分开：未满足回复规则，不代表消息不需要记录。

发送超时时保留“结果待确认”，而不是直接认定失败并立即重发。实时事件与历史补拉共用去重机制，降低重复处理风险。

接收诊断用于区分协议端未上报、连接异常、规则跳过和模型失败。历史补拉是恢复辅助，受协议端支持和可用历史限制，不保证找回全部遗漏消息。

### 三种响应模式

人设决定“如何说话”，响应模式决定“何时说话”，两者独立配置。

| 模式 | 行为 |
| --- | --- |
| 安静型 | 优先回应 @bot、呼叫词或对 bot 消息的引用；普通群聊参与默认关闭，可单独开启 |
| 均衡型 | 回应直接呼叫、相关上下文和明确的负面情绪；普通群聊参与可设置开关与概率 |
| 活跃型 | 在上述基础上提高普通群聊参与概率，支持按时间和概率进行主动破冰 |

未选中的消息不进入普通模型生成流程。群聊总开关、接入范围、关键词规则和专门的跟发流程仍会限制响应，活跃型不代表无条件回复每条消息。

可配置短暂收集窗口，将连续消息合并处理，减少逐条追答。只有需要回应且满足识图条件时才进行图片处理，不因收到无关图片或表情就强制识图。

### 人设、关系与好感度

支持自定义角色提示词、人设卡片及头像。关系按真实发送者 QQ 查询，可配置称呼、关系备注和适用范围；指定群关系优先于全局关系。

全局好感度可在后台修改，并通过六档规则影响文字上限和表情概率。默认值如下，具体上限与概率可在后台编辑：

| 好感度 | 单轮文字上限 | 表情触发概率 |
| --- | --- | --- |
| 0–39 | 15 字 | 10% |
| 40–79 | 20 字 | 25% |
| 80–119 | 30 字 | 45% |
| 120–159 | 40 字 | 65% |
| 160–199 | 45 字 | 80% |
| 200 及以上 | 50 字 | 90% |

上限不是要求写满。好感度用于调整表达长度和亲近程度，不改变基础人设，也不会赋予主人权限。排行榜等结构化结果使用独立规则，避免名单被普通回复长度限制截断。

### 中文互动

以下写法中的 `@bot` 表示实际提及登录账号，不是手动输入这四个字符：

| 指令示例 | 功能 |
| --- | --- |
| `投喂 @bot` | 投喂互动，按配置增加好感度 |
| `散步 @bot` | 散步互动，按配置增加好感度 |
| `摸摸头 @bot` | 摸头互动，受每日次数限制 |
| `签到 @bot` | 本地记录签到 |
| `签到排行榜 @bot` | 查询签到排名 |
| `今日运势 @bot` | 查询当天运势 |
| `好感度 @bot` | 查询好感度 |
| `好感度排行 @bot` | 查询排名 |

互动开关、每日次数、增加数值和排行人数可配置。模型生成的互动文本使用已配置人设；未配置模型时，不提供凭空生成的 AI 回复。指令列表及管理指令仅指定主人可用。

### 表情包

表情素材支持收藏、标签、情感备注和场景匹配。触发概率表示尝试发送的概率，不保证任何场景都有可用素材。

每轮最多附加一张表情，并结合冷却、匹配和好感度规则执行。启用好感度阶梯时，概率由对应档位控制；没有合适素材时静默跳过，不将内部“未找到”提示发送到对话中。

### 主备模型与调用节制

支持配置多个 OpenAI 兼容提供商，获取模型目录并选择模型；备用模型有自己的接口、密钥和超时配置。符合切换条件时尝试备用服务，不能保证所有 API 错误都能无损继续。

调用链具有有限重试和等待策略，避免持续触发限流。后台可查看用量及按设置单价估算的成本，估算不等同于服务商实际账单。

签到、排行、关系、好感度和每日记录优先读取本地数据。互动回复按条件缓存，并可配置补充预算；普通聊天不会为了提高命中率直接复用整段旧答案。

本地回复缓存与服务商输入缓存是两回事，后者是否命中及如何计费由模型服务决定。

### 群聊跟发与原生接龙

开启对应功能后，在白名单群的统计窗口内，三位不同用户发送一模一样的纯文字，bot 原样发送相同内容一次。参与记录本地保存，防止相同内容反复触发；这不是在原文后机械追加“+1”。

普通文字跟发与 **QQ 原生接龙按钮**不是同一功能。项目具有原生结构捕获与相关处理入口，但是否能参与取决于 NapCat 对消息结构和提交接口的支持，不能保证模拟点击原生“+1”。不能参与时不冒充成功。

## 项目结构

```text
bot-admin/
├── 一键部署启动.cmd          # 首次部署与启动
├── 启动管理后台.cmd          # 后续启动入口
├── start.mjs                 # Windows 启动入口
├── gateway.js                # 管理认证与后台代理
├── .env.example              # 环境变量示例，不含实际密钥
├── scripts/                  # 下载校验、环境准备、快捷方式及进程管理
├── onebot/                   # 协议配置模板与配置工具
└── qq-agent/
    ├── src/                  # 接收、回复、模型、互动、缓存、诊断等后端
    ├── ui/                   # 管理后台页面与动效资源
    ├── test/                 # 随发行包提供的测试
    ├── package.json          # 后端依赖
    └── LICENSE               # 原项目许可
```

首次运行后产生以下本地目录，**不属于公开发行内容**：

```text
.runtime/                    # Node、QQ/NapCat 和下载缓存
data/                        # 管理密码、部署记录、QQ 独立资料
qq-agent/data/               # 业务配置、数据库、消息、会话与素材等
qq-agent/node_modules/       # 安装后的生产依赖
```

运行日志可能位于控制台、数据目录或 QQ 运行目录中，分享诊断文件前同样需要检查隐私。

## 端口与环境变量

| 服务 | 默认本地端口 | 说明 |
| --- | --- | --- |
| 管理入口 | 8080 | 默认访问 `http://127.0.0.1:8080/qqbot/` |
| 业务后端 | 3210 | 供管理入口连接 |
| OneBot HTTP | 3000 | QQ 协议 API |
| OneBot WebSocket | 3001 | QQ 消息事件 |
| NapCat WebUI | 6099 | 协议端管理接口 |

首次部署遇到占用会选择附近空闲端口，并记录实际配置。以启动输出为准，不要把示例端口当成固定结果。

| 环境变量 | 用途 |
| --- | --- |
| `ADMIN_PASSWORD` | 自定义管理密码，至少 12 字符；留空则随机生成 |
| `BOT_OPEN_BROWSER=0` | 禁用自动打开浏览器和密码记事本 |
| `BOT_USE_LOCAL_NODE=1` | 强制使用项目下载的便携 Node |
| `BOT_SKIP_PROTOCOL=1` | 排障时仅启动后台，不提供 QQ 收发 |

可复制 `.env.example` 为 `.env` 后按需配置。正常一键部署不要求手工设置这些变量。

默认面向本机使用，内部服务绑定回环地址。不要把 OneBot、业务后端或 QQ WebUI 直接公开到互联网；远程访问需要另行配置 HTTPS、防火墙、访问控制和安全的管理入口。

## 常见问题

### 下载卡住或部署失败

检查 GitHub、Node.js 官网和 npm 的网络访问。首次 QQ 运行包约 119 MB，后续会复用环境。校验失败的文件不会执行，不要跳过校验或自行换成不明来源文件。

运行库安装要求管理员确认时需要本人允许。如果系统要求重启，重启后再次运行部署入口。

### 后台能打开，但 QQ 还不能收发

先看 QQ 真实登录状态及 OneBot 连接状态。服务运行不等于账号在线，扫码页面出现不等于已经登录；未知状态也不应视为成功。

### QQ 在线，却没有回复

依次检查接入白名单、群聊总开关、响应模式、呼叫词、普通参与开关与概率、互动开关和模型设置，再查看接收诊断、会话记录与 API 错误。

如果后台完全没有对应消息，应先排查事件连接和协议上报；修改人设或提高回复概率不能解决“没有收到事件”。

### 表情概率为 100%，仍然没有表情

检查是否有可用素材、标签和备注是否匹配、是否处于冷却，以及好感度阶梯是否覆盖了基础概率。100% 不会绕过素材缺失、匹配失败或发送规则。

### 需要验证，能否完全自动登录

不能绕过 QQ 的安全验证。自动恢复仅在已有可用登录状态或允许的登录方式下尝试，遇到验证码、设备确认等情况需要人工处理，不承诺永久在线。

### 可以把运行过的目录直接上传 GitHub 吗

不建议。运行后目录会产生账号、密钥、消息、缓存及素材等私人数据。应上传未运行过的空白源码/发行包，不能只依赖 `.gitignore` 判断压缩包安全。

## 隐私与发布

公开包不预填个人 QQ、主人、API 地址及密钥、人设、头像资料、关系、聊天记录、记忆、表情素材或登录数据。通用端口、功能规则与示例文件不属于私人配置。

发布前至少排除并复核：

- `.env` 及实际环境配置。
- `data/`、`qq-agent/data/`、数据库和数据库附属文件。
- `.runtime/`、QQ 登录缓存、协议配置和令牌。
- 日志、会话、聊天记录、记忆、上传素材和截图。
- `node_modules/` 及测试中生成的运行目录。

不要把“本地存储”理解成“任何信息都不会发送到外部”。启用模型、识图或联网功能时，相关消息、图片、提示词和必要上下文会按功能发送给所配置的服务，请自行评估提供商隐私政策并告知使用者。

## 验证范围

Windows 发行流程已验证：自动准备便携 Node、官方 QQ 运行包下载和校验、QQ 数据隔离、真实登录接口及二维码、桌面快捷方式、重复启动保护、QQ 服务停止与重启，以及桌面/移动宽度下的登录页面。
